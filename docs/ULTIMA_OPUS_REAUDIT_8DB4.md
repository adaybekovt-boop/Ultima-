## Runtime flag semantics

| Query | Before | After |
| --- | --- | --- |
| `isEnabled(key)` (UI, commands, init, reporting) | live resolution | unchanged |
| `resolve(key)` reason | live | unchanged |
| `hasPendingRestart(key)` | `launch != live` | unchanged |
| Hot gate | `isEnabled(key)` | `launch && live`, O(1), no allocation |

The two hot-gate forms differ only when a module was off at launch and is requested on later. Its Mixins are not applied, so the hot code is unreachable; the new form fails closed there. A UI disable still stops runtime work immediately, because `setRequested` rebuilds the table. `ForensicRegressionTest.testRuntimeModuleFlags` covers launch on/off, UI disable/re-enable, pending restart, dependency propagation, the Lithium block, unknown and out-of-range indexes, 300 randomized `setRequested` sequences against `wasEnabledAtLaunch && isEnabled`, and zero allocation over 1 000 000 probes.
