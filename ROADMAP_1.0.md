# Ultima → 1.0: карта финальной доработки

Документ для агента (Claude Code / Cursor) и для владельца репозитория.
Составлен по `main` @ `e6763a8` и открытым PR на 2026-09-28. Работай по фазам сверху вниз:
следующая фаза начинается только после того, как у текущей выполнен «Выход».

---

## 0. Где проект сейчас — честно

**Что есть**
- 24 модуля, ~31.7k строк Java, 56 common + 26 client Mixin'ов, большой JavaExec-харнесс.
- CI на `main` зелёный (build + регрессии + headless `runServer` Mixin smoke).
- Архитектура модулей правильная: `UltimaModules` → `UltimaMixinPlugin` гейтит Mixin'ы,
  автоотключение при Lithium/Canary/Radium и Sodium/Iris/Canvas, fail-open-двери.

**Чего нет — и это главное**
1. **Ни одной runtime-проверки клиента на текущем коде.** Единственный замер FPS
   (+30.8%, `retained_terrain`) сделан примерно 150 коммитов назад, а модуль выключен по умолчанию.
   Единственный замер сервера (−21.8% ms/tick) — тоже исторический.
2. **На самом частом стеке игрока (Sodium + Iris + Lithium) Ultima почти ничего не делает:**
   рендер-модули и Lithium-пересекающиеся модули отключаются, остаются `cursor_step`,
   `server_metrics` и `settings_ui`.
3. **Больше 40 PR и веток ушли на статический «hardening» без запуска игры.** Это петля:
   каждый раунд чинит то, что нашёл прошлый аудит, но доказательной базы не прибавляется.
   **Главное правило 1.0: каждая фаза заканчивается запущенной игрой, а не ещё одним аудитом.**
4. `temporal` включён по умолчанию, но бэкенда у него нет: работа на каждом кадре без эффекта.
   `terrain_metrics` включён по умолчанию, но нужен только бенчмарку.
5. Нет `LICENSE`, иконки, нормального README для игроков и релизного пайплайна.
   В репозитории лежит zip-снапшот исходников на 525 KB.

**Незамерженная работа (стек поверх `main`)**
- `#39` → `#41` → `#42`: цепочка поверх `main`. В ней: `temporal`/`terrain_metrics` выключены
  по умолчанию, `isEnabled` без аллокаций, Lithium-гейт для `cursor_step`, исправлен overflow
  в `CursorMath`, единый `./gradlew test`, закоммиченный wrapper, упрощённый CI.
  **Это нужный фундамент для 1.0.**
- `#37`, `#38`: ветка `agent/killer-modules-v1` (Iris artifact cache, admission broker, warmup).
  Аудит `#36` показал, что это не результаты производительности: на реальном Iris ключ кэша
  не строится, broker отменяет весь deferred submit. **В 1.0 не входит.**
- `#3`, `#4`, `#18`: устарели (mesher влит через интеграцию, `#18` заменён `#20`).
- `#36`, `#40`: только документация и аудит. Полезное из них учтено в этой карте.

## 1. Определение продукта 1.0 (решение, а не вариант)

**Ultima 1.0 — оптимизация симуляции для сервера и хоста LAN, плюс опциональные рендер-модули
для игроков на ванильном рендере.** Гости подключаются ванильным клиентом.

- По умолчанию включено только то, что прошло runtime-проверку (Фаза 3) и не пересекается
  с Lithium/Sodium.
- Совместимость с Sodium/Iris/Lithium значит «не ломает и не дублирует», а не «ускоряет поверх».
  В README это пишется прямо.
- Рекламное «2x fps» из описания репозитория убрать: у текущего кода такого замера нет.

### Фаза 1 — вычистить продукт (1–2 дня)

**Задачи**
1. **Удалить `temporal` целиком:** модуль, Mixin'ы, `dev.ultima.temporal`,
   `dev.ultima.client.temporal`, строки в настройках и тесты. Бэкенда нет, пикселей он не меняет,
   а FSR от него не зависит (`dependencies` пустой). Сначала проверь приоритеты `GameRenderer`
   в FSR-Mixin'е: комментарий в `temporal/GameRendererMixin` ссылается на порядок с FSR.
2. **Код, который реально используется только тестами и бенчмарками, перенести из `src/main`
   в `src/test`** (или в отдельный source set `bench`). Кандидаты: `CpuMeshingBenchmark`,
   `MesherBenchmarkScenes`, `MesherWorldFixtures`, `VanillaCubeOracle`, `VanillaVisitOracle`,
   `VanillaCubeCoverage`, `FsrSkySafetyModel.SkyRendererStub`.
   Перед переносом проверь каждый через grep: например, `SectionFixtures` используется
   в продовом `FastPathCriteria`, значит имя вводит в заблуждение и класс нужно переименовать,
   а не переносить.
3. `EntityQueryKind` в `src/main` сравнивает строки с именами `net.minecraft.client.*`.
   Это не загрузка классов, но добавь проверку в `VanillaClientHostingChecks`,
   что в `src/main` нет ни одного `import net.minecraft.client` и `com.mojang.blaze3d`.
4. **Решение по каждому экспериментальному рендер-модулю — через Фазу 3, но с жёстким правилом:**
   модуль либо показывает замеренный выигрыш ≥ 3% в своём сценарии без визуальных различий,
   либо **удаляется из кода**, а не остаётся «default off навсегда».
   Первые кандидаты на удаление: `rgss_endpoint` (36 строк, условие «≥ 3% GPU» ни разу
   не проверялось), `java_mesher` (при `mesher_fast_path` он проигрывает по определению),
   `render_snapshot`, `section_task_queue`.
5. Обнови `UltimaModules`, `UltimaSettingsCatalog`, `MergedModuleContractTest`, README и
   `MODULES`-индекс на итоговый список.

**Выход:** build зелёный, сборка jar меньше, в `src/main` нет тестовых фикстур,
число модулей соответствует README.

### Фаза 2 — runtime-харнесс: игра запускается сама (2–3 дня)

Это ключевая фаза. Без неё 1.0 невозможна.

**Задачи**
1. **Серверные gametest'ы** (`fabric-gametest-api-v1`, `./gradlew runGametest`) для модулей
   симуляции. Каждый тест запускает сценарий дважды, с модулем и без (через
   `UltimaConfig.createForTests`, либо двумя прогонами JVM с разными `ultima.properties`),
   и сравнивает итоговое состояние мира.
   - коллизии: мобы и игрок-фейк в узких проходах, на лестницах и плитах, в `powder_snow`,
     на краях чанков, с отрицательными координатами → позиции совпадают побитно;
   - хопперы, сундуки, печи, двойные сундуки, вагонетки с воронкой → содержимое через N тиков
     совпадает (для `blockentity_sleeping` и `container_slot_mask`);
   - крафт, печь, варка при перезагрузке датапака (`/reload`) → те же результаты
     (для `recipe_match_cache`);
   - теги после `/reload` (для `tag_bitsets`), pathfinding по полю препятствий
     (для `state_property_cache`), стрелы, предметы и опыт рядом с пустыми секциями
     (для `entity_query_early_out`).
2. **Клиентский gametest** (`fabric-client-gametest-api-v1`, если он есть в Fabric API
   `0.156.0+26.2`; проверь по `.agent/vanilla-src` и зависимостям) под `xvfb-run` с Mesa llvmpipe
   в CI. Сценарий: создать мир → облететь 3 точки → открыть экран настроек Ultima →
   переключить FSR-пресет → выйти. Снять скриншоты с модулями и без них, сравнить попиксельно
   с допуском (для рендер-модулей, которые должны быть pixel-identical: `mesher_fast_path`,
   `retained_terrain`).
3. Добавить в CI job'ы `runGametest` (Linux) и client gametest (Linux + xvfb).
   Старый `mixin-smoke.sh` оставить: он дешёвый.
4. **Матрица совместимости в CI** (только загрузка, без бенчмарка): Ultima + Lithium,
   Ultima + Sodium, Ultima + Sodium + Iris, Ultima + Mod Menu. Моды качаются с Modrinth
   в `run/mods` по закреплённым версиям. Проверяется, что игра стартует, в логе нет
   `Mixin apply failed`, а `/ultima config` показывает ожидаемые `reason=incompatible_mod`.

**Выход:** CI запускает настоящий сервер и настоящий клиент, для каждого модуля симуляции есть
дифференциальный gametest, матрица совместимости зелёная.

### Фаза 3 — замеры и решение по дефолтам (владелец + агент, 2–4 дня)

Агент готовит сценарии и скрипты, владелец запускает их на реальном ПК
(в облаке нет GPU).

**Задачи**
1. **Сервер** (`scripts/bench-server-ab.sh`): entity farm, hopper-хаб, авто-крафт,
   мир с 20 игроками-ботами. По 6 пар A/B с чередованием; метрики: MSPT среднее, p99,
   аллокации (JFR). Порог включения по умолчанию: ≥ 3% MSPT, 95% CI не пересекает 0,
   нулевые расхождения в gametest.
2. **Клиент, ванильный рендер** (`scripts/bench-client-ab.sh`): stationary, yaw sweep,
   chunk-flight. Метрики: средний FPS, 1% low, p99 frame time. Тот же порог.
   Отдельно визуальный diff скриншотов.
3. **Клиент, Sodium + Iris + Lithium:** только проверка, что ничего не ломается и нет
   регрессии в пределах шума. Выигрыша здесь не ожидается, и его не нужно заявлять.
4. Результаты — в `BENCHMARKS.md`: SHA, железо, JVM, сиды, сырые CSV. Никаких чисел
   без SHA, равного релизному.
5. **Применить решения:** прошёл порог → `default on`; прошёл gametest, но не порог →
   `opt-in` с честным описанием; упал или показал регрессию → удалить.

**Выход:** у каждого оставшегося модуля есть строка в `BENCHMARKS.md` с вердиктом,
дефолты в `UltimaModules` соответствуют вердиктам.

8. Финальная ручная проверка на ПК владельца: чистый профиль, клиент с одной Ultima +
   Fabric API; выделенный сервер плюс ванильный клиент-гость; Open to LAN плюс ванильный гость;
   клиент с Sodium + Iris + шейдерпаком. Всё без крашей и с чистым логом.

**Выход:** тег `v1.0.0`, jar в GitHub Release, README и BENCHMARKS соответствуют коду.
